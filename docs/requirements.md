# IIDXリザルトOCR→BPI計算PWA 要件定義

出典: Claude Docs「IIDXリザルトOCR→BPI計算PWA 要件定義」(2026-11-26)。本ファイルはその転記と、実装時の追加決定（末尾）を含む。

## 概要・目的

beatmania IIDX のリザルト画面を撮るだけで、曲・譜面・EXスコアを読み取り、BPI を返す PWA。リザルトを記録する手段として「普段のカメラアプリの代わりに使う定番」になることを目指す。

成功指標: 起動→読み取り完了 2 秒以内 / 数字の精度 99.9% 以上 / 曲・譜面特定 99% 以上 / 確認操作なし確定 95% 以上 / アプリを閉じず連続撮影。

## 機能要件

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| F1 | カメラ撮影 | 背面カメラ映像に白枠ガイドを重ね、モニター全体を枠に合わせる | 必須 |
| F2 | 自動推論 | ブレなし・静止・画面検出成功で自動読み取り。連続 2〜3 フレーム同値＋検算一致で確定 | 必須 |
| F3 | シャッターボタン | 押した瞬間のフレームで読み取る | 必須 |
| F4 | 画像取り込み | 端末内画像（e-amusement アプリ保存画像・カメラ写真）。斜めは四隅指定で補正 | 必須 |
| F5 | 曲・譜面の特定 | 難易度＋レベル＋SP/DP＋ノーツ数で絞り込み、曲名 OCR は決め手。低確信時は上位 3 件を候補表示 | 必須 |
| F6 | スコア読み取り | EX スコア（ベスト・今回・差分）、判定内訳、FAST/SLOW、BP、クリアタイプ、DJ LEVEL、USE OPTION、NEW RECORD | 必須 |
| F7 | BPI 表示 | 確定した曲・譜面・EX で BPIM2 API を呼び BPI と推定順位を表示 | 必須 |
| F8 | 修正 | 読み取り結果を手で直せる。修正は次回から照合に使う | 必須 |
| F9 | 履歴 | 元画像と結果を端末内に保存し一覧・検索 | 必須 |
| F10 | 曲データ更新 | 起動時にメタデータ確認、更新があれば自動更新 | 必須 |
| F11 | BPIM2 への登録 | 読み取ったスコアを BPIM2 に登録（要認証） | 推奨 |
| F12 | 2P 側・DP 対応 | レイアウト差への対応 | 推奨 |
| F13 | 結果表示 | 成功したら Vaul ドロワーで下から表示 | 必須 |
| F14 | X へのシェア | 画像に曲名・スコア・判定内訳・BP・ランプ更新・BPI を添える | 必須 |
| F15 | カメラロール保存 | Android は自動 DL、iOS は 1 タップ（まとめて保存） | 必須 |
| F16 | 統計データ送信 | 枠の切り出しと撮影した写真の全体（縮小・EXIF 除去）を R2、読み取りデータを DB へ（同意制） | 必須 |
| F17 | 設定画面 | 自動撮影・シェア・保存・統計・BPIM2 連携の ON/OFF | 必須 |
| F18 | 初回起動 | 追加データ DL、BPIM2 ログイン、統計同意 | 必須 |

## 結果表示（Vaul）と X シェア

- 確定でドロワーを半分の高さで自動表示。上スワイプで全項目、下スワイプで閉じて次の撮影へ。カメラは裏で動かし続ける
- 項目: 曲名・譜面、EX とベスト差、BPI、判定内訳、BP、ランプ更新、DJ LEVEL、USE OPTION。ボタン: シェア・保存・修正
- シェア: Web Share API で画像＋本文。非対応時のみ intent URL で本文を渡し画像は保存。画像は「写真」か「結果カード」を設定で選択。本文はテンプレート（設定で編集可）、更新時は差分付き

本文の例:

```
HEARTACHE [SPA☆10]
EX 1796（更新 +1796）AAA
BPI xx.xx
F-COMBO / BP 0
PG 867 / GR 62 / GD 1 / BD 0 / PR 0
#IIDX #BPI
```

## カメラロール保存

アプリ内履歴は常に自動保存。Android は確定時に自動ダウンロード。iOS はドロワーの「保存」→共有シート「画像を保存」、撮影終了時に未保存分を 1 回でまとめて保存。完全自動はネイティブ化（Capacitor 等）が必要。

## 統計データ送信（同意制）

| 種類 | 中身 | 保存先 |
| --- | --- | --- |
| 画像 | 台形補正した画面部分のみ、長辺 1280px 程度の WebP | R2 |
| 読み取り結果 | 譜面 ID、EX、判定内訳、FAST/SLOW、BP、クリアタイプ、DJ LEVEL | DB |
| プレー条件 | USE OPTION、自己ベスト更新有無、ベストとの差 | DB |
| 読み取りの質 | 項目別確信度、修正項目と修正前値、カメラ/取り込み、アプリ・モデル版 | DB |

匿名化: 画面外を切り捨て・EXIF 除去・DJ NAME/店舗名を塗りつぶし・端末ランダム ID のみ（BPIM2 アカウントと結び付けない、リセット可）。署名付き URL で R2 へ直接送信、IndexedDB に溜めて通信可能時にまとめ送信、撮影速度に影響させない。

## 設定画面と初回起動

設定: 自動撮影(オン)/カメラロール保存(オン)/シェア画像(写真)/シェア本文テンプレ(標準)/統計送信(同意に従う)/統計に画像を含める(オン)/BPIM2 登録(ログイン時オン)/BPIM2 ログイン・ログアウト/端末 ID リセット・履歴削除。

設定はトップを一覧にし、項目ごとのページに分ける。

- アカウント連携: BPIM2（サインイン・スコアログ）と beat-seeker（連携トークン）のページ、両方に共通の同期先（既定）
- カメラ設定: 撮影枠の位置、プレーサイド、使うカメラ、自動撮影、カメラロールへの保存、シェアに写真を添える
- 読み取り設定: 読み取りの処理（GPU / CPU）
- モデル: 取得済みのモデル
- 統計データ: 送信の同意、画像を含める、学習データ、端末 ID のリセット
- トップに残すもの: ホーム画面に追加、デバッグモード、ライセンス、履歴の削除、バージョン

初回起動: ①データ DL を裏で開始（曲マスタ・数字モデル・読み取り位置設定。日本語 OCR は後回し）②BPIM2 ログイン（スキップ可）③統計同意 ④カメラ許可 ⑤iOS Safari ならホーム画面追加案内 ⑥DL 完了で撮影画面へ。途中終了しても再開できる。

## 認識方式

数字は Tesseract を使わず、色で文字を抽出して小さな分類器で読む。曲は譜面の条件で特定し、曲名 OCR は補助。「EX＝PGREAT×2＋GREAT」の検算が合うまで確定せず次フレームで読み直す。

- 画面検出: 暗い筐体に対し画面が明るい→四隅検出→台形補正→固定位置を切り出し
- 数字分類器: 見本との形比較、または数十 KB の小さな CNN
- 曲名 OCR: 白文字のみ二値化→曲マスタと編集距離で照合、アーティスト名も使用

## データ・API

- `GET https://bpi2.poyashi.me/api/v2/bpi/calc`（認証不要）。パラメータ `title`/`difficulty`/`exScore`/`version`/`includeRank`。レスポンス `song`/`bpi`/`rank`/`metadata`。返却ノーツ数と読み取りノーツ数を照合して取り違えを検出
- IndexedDB: `songs`（正式名・正規化名・アーティスト・別名）/`charts`（曲 ID・SP/DP・難易度・レベル・ノーツ）/`history`/`aliases`（OCR 結果→曲 ID）/`meta`（データ版）
- 更新: 起動時に ETag 付きでメタ取得→新しければ BPIM2 楽曲マスタから差分反映。読み取り位置設定も同じ仕組みで配信

## 非機能要件

| 項目 | 目標 |
| --- | --- |
| 起動→カメラ映像 | 1 秒以内 |
| 確定→BPI 表示 | 300ms 以内 |
| 1 フレーム自動撮影判定 | 10ms 以内（縮小画像） |
| 数字読み取り | 1 画面数十 ms |
| 曲名 OCR | 0.5 秒以内（必要時のみ） |
| UI | メインスレッドを止めない、60fps |
| オフライン | 読み取り・履歴は通信なし。BPI は復帰後 |
| 対応端末 | iOS Safari 17+、Android Chrome 最新、PWA |

実装方針: `requestVideoFrameCallback` + `createImageBitmap` → Worker の OffscreenCanvas。OCR Worker は起動直後に立ち上げ、データは Service Worker でキャッシュ。日本語学習データは必要時のみ読み込み。

## リスク

iOS PWA のカメラ許可再確認 / 新バージョンでレイアウト変更（設定配信で対応）/ 2P・DP・筐体差（サンプル収集）/ モアレ（複数フレーム＋検算）/ 撮影禁止店舗（画像取り込み）/ iOS 自動保存不可 / 統計画像の個人情報 / X 共有で本文が落ちる端末（クリップボードにも入れる）。

未確認: BPIM2 API の CORS と制限 / 譜面一意性 / 登録 API 仕様と認証 / 2P・DP レイアウト / ログイン方式 / DJ NAME 位置 / 統計サーバー構成。

## 開発フェーズ

1. 検証 2. 画像取り込み版（画面検出・数字読み取り・譜面特定・BPI・曲データ更新・初回起動）3. カメラ版（白枠・自動撮影・連続撮影・履歴・Vaul・保存・X シェア・設定・統計）4. 曲名 OCR（Tesseract vs PaddleOCR）5. 拡張（BPIM2 登録・2P）

## 実装時の追加決定

- **☆10 以下の扱い**: 曲マスタは BPIM2 の `allSongs`（全難易度・☆1〜12）を使い、☆10 以下も読み取り・履歴・X シェアの対象にする。BPI 計算 API は ☆11/12 のみ対応のため、☆10 以下は API を呼ばず「BPI 算出対象外」と表示し、BPI 行をシェア本文から外す。将来の追加指標のため、結果モデルは `bpi: number | null` + `bpiStatus: 'calculated' | 'unsupported-level' | 'pending' | 'error'` を持つ
- **曲マスタ取得**: 現行の公開 `GET /api/v2/songs` は songs テーブル（☆11/12）のみ。allSongs 配信用エンドポイント（BPIM2 側）が別途必要。それまで `public/data/songs-master.json` のシードで動かす
- **UI**: shadcn/ui + Hallmark の Floor（app スコープ）。ブランド色・グラデ・絵文字アイコンなしの実用的な見た目
- **サンプル**: `D:\camera-example`（1p プレビュー 4 枚、2p 写真 3 枚）。リポジトリには含めない
